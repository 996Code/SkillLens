# Active Probing 主动探测——设计评估（块 N5，v3 §16）

> 状态：设计文档（未实施）。实施闸口 **G6：可重置测试环境授权**——主动探测需要对目标系统执行试探性输入（如边界值提交），必须满足 C1（副作用门控）且环境可重置/可撤销。
> 依据：v3 §16"纯被动观察不够"——观察 5000/8000→普通审批、20000/50000→经理审批，猜测 `amount > threshold`，再主动测 9999/10000/10001 收敛规则。

## 一、问题：被动学习学不到"条件规则"

当前管道只学"做了什么→发生了什么"（Action→Outcome），学不到**分支条件**：
- 审批级别取决于金额阈值——被动观察要凑齐各金额段样本才能归纳，真实流量可能永远缺边界样本
- 表单校验规则（必填/长度/格式）——只有违反时才可见
- 权限边界——只有越权尝试时才可见

## 二、设计：三段式探测循环

```
①规则猜测（确定性）
   输入：evidence_edge 中同一 action 下不同输入→不同 outcome 的样本对
   方法：按输入字段值排序找分割点（一维阈值）/ 决策树归纳（多维，v2）
   产出：hypothesis: {field, op: ">", threshold: 10000} → outcome_class
   置信：样本间距/覆盖度计算，间距越小置信越高（9999 vs 10001 之间 → 高）

②探测计划（LLM 结构化，人工确认）
   生成边界输入集：threshold-1 / threshold / threshold+1（±安全余量）
   计划含：目标 Skill、注入字段、输入值、预期 outcome_class、回滚方式
   人工确认后生效（C1 延伸：探测属"主动副作用"，默认 shadow 只出计划）

③执行与收敛（复用回放通道）
   经 Replay Runner 换参数执行（现有 overrides 机制）
   结果回填：假设成立 → hypothesis 升 validated，写入 evidence_edge（type="implies"）
   不成立 → 更新分割点，回到①
```

## 三、与现有架构的衔接

| 现有机制 | 复用点 |
|---|---|
| Skill input_variables | 探测注入字段即变量 |
| Replay overrides | 探测输入注入通道 |
| C1 门控 | 探测计划默认 shadow，确认才执行 |
| evidence_edge | 假设与验证结果落边（新 type="implies"，src=条件表达式 dst=outcome） |
| outcome_assertion | validated 规则生成新断言 kind="rule"（层4 历史样本背书） |

## 四、安全与边界（G6 闸口内容）

1. **环境要求**：探测目标必须是可重置环境（测试系统/沙箱租户）；生产系统仅允许"只读探测"（不提交，只观察查询类边界）
2. **频率限制**：每假设 ≤3 次探测（9999/10000/10001 模式），防打爆目标
3. **回滚**：探测产生的数据变更须有对应清理 Skill 或环境快照恢复
4. **审批**：探测计划人工确认环节不可省（与 Expected Delta confirm 同级）
