# SkillLens SWOT 与迭代方向分析（对照宪法 §11 参照系）

> 日期：2026-09-25。输入：MVP→S15 全程实施记录 + 块 P 公网实测 + 宪法 §11 竞品调研 + v3 原始设想。
> 用途：主计划下一轮迭代的优先级依据。

## 一、优势（Strengths）——竞品短期补不上的

| # | 优势 | 证据 | 对位竞品 |
|---|---|---|---|
| S1 | **Evidence-backed 全链路**：raw_event→delta_report 每级落库可回溯（C3），失败 LLM 调用也落 | /audit 一条链点到底；S7 异常落库 | Katalon/Meticulous 无证据图概念 |
| S2 | **四分类变更智能**：Expected/Missing/Unexpected/Drift 确定性判定 | S11 两次真实发版：expected 正向命中 + 回归面验证 | 无人做"需求预期 vs 实际"分类 |
| S3 | **C1 影子门控**：编译期定格、行不可变、零 launch 硬断言 | S13-S15 审查四路核实 | 企业级安全叙事的硬差异点 |
| S4 | **私有化架构级默认**：数据不出网/客户自带 key/Docker | S6 压轴 E2E 139s | 国内客户辨别"伪私有化"（§11.3） |
| S5 | **泛化鲁棒性实证**：陌生系统（新浪/antd）零改动全链 PASS | 块 P | 多数工具绑定特定框架 |
| S6 | **LLM 边界纪律**：只命名/结构化/归因，判定全确定性+人工确认 | 7 个 Sprint 零 LLM 判定事故 | "LLM Judge 有系统性盲区"（§11.2）的反面 |

## 二、劣势（Weaknesses）——实测暴露的

| # | 劣势 | 证据 | 影响 |
|---|---|---|---|
| W1 | **语义定位依赖目标系统可访问性**：无 placeholder/aria 时回退框架 id（不稳定） | 块 P：antd rc_select_0 | 换页面/换会话可能定位失败——块 L 前置 |
| W2 | **回放路径外不可见**：新功能/页载 GET 不进 observed | S11 边界①② | Missing 误报需人工甄别（N1/N2 已缓解一半） |
| W3 | **单租户单系统深度**：所有深度验证都在 njmind+新浪两个浅任务族 | G5 刚满足 | 复杂系统（多级审批/表格编辑）未验证 |
| W4 | **UI 工程性弱**：手写 CSS、无设计系统、信息密度未打磨 | 用户指令③ | 演示/评审第一印象受损 |
| W5 | **无真实团队使用数据**：所有"真实流量"是 Agent 模拟 | S10 | M2"团队认可"待用户核签 |
| W6 | **夜间开发未落地**：G 块卡 G3 | M3 半闭环 | Phase 3 叙事缺口 |

## 三、机会（Opportunities）

| # | 机会 | 依据 |
|---|---|---|
| O1 | **黑盒无源码 spec 验证空位**（§11.2：SDD 浪潮全假设有代码仓库） | 竞品无人占位，窗口在收窄 |
| O2 | **国内私有化+信创**：架构级承诺已就绪 | §11.3 需求信号 |
| O3 | **通用能力层（块 L）**：G5 语料已就位（2 任务族），槽位映射若成 → "学一次迁移一片" | 块 P 泛化实证 |
| O4 | **公网站点即销售素材**：新浪闭环 PASS 是 30 秒 demo 素材 | 块 P |

## 四、威胁（Threats）

| # | 威胁 | 对策 |
|---|---|---|
| T1 | Katalon"需求直出脚本"叙事挤压 | 坚守四分类+证据图差异（宪法 §11.1 已预判） |
| T2 | 巨头进场（UiPath dark testing factory） | 深耕私有化+国内信创 |
| T3 | LLM 能力同质化（Browser Agent 泛滥） | S6 边界纪律是工程护城河不是话术 |

## 五、迭代优先级建议（下一轮主计划输入）

| 优先 | 方向 | 理由 | 对应 |
|---|---|---|---|
| P0 | **UI 升级（块 Q）** | W4——演示/评审第一印象，用户明确指令 | 用户指令③ |
| P0 | **语义定位强化**：采集侧跳过框架 id + 定位多策略 | W1——泛化的最后一公里 | 块 L 前置 |
| P1 | **通用能力层（块 L）启动** | G5 已满足（O3）——最大差异化跃迁 | 主计划块 L |
| P1 | **复杂任务族验证**：多级表单/审批流（njmind 请假表单可用） | W3——深度不足 | G5 深化 |
| P2 | **真实团队使用** | W5——M2 出口硬前提 | G2/G4 |
| P2 | **夜间开发（G 块）** | W6/T1——需 G3 授权 | 闸口 |

> 结论：**产品骨架已完整且经陌生系统验证**；下一轮价值最高的是 UI 打磨（可感知）+ 语义定位强化（可靠性）+ 块 L 通用化（叙事跃迁）。
