# 竞品 UI 差距分析（2026-09-28，浏览器实地调研）

> 方法：browser-use 实访 Katalon TrueTest 产品页 + WebFetch 调研 Applitools/QA Wolf/Mabl/Testim。
> 结论：我们的工作台与业界测试平台的 UI 差距是**代际级**的——不是样式问题，是信息架构与可视化密度问题。

## 一、竞品 UI 模式清单（实地所见）

### Katalon TrueTest（浏览器实访，最直接参照）
| 模式 | 具体形态 |
|---|---|
| **标签页主导航** | Tests / Journey maps / Coverage gap 三标签切换 |
| **数字统计卡** | "Flows 3 / Pages 4 / Actions 5" 大数字+标签 |
| **环境对比徽章** | "PRODUCTION storefront-prod" vs "TEST SUITE storefront-qa" 并排 |
| **时间范围选择器** | "Last 30 days" 下拉 |
| **覆盖缺口可视化** | Uncovered flows 列表（名称+流量数字），"Top 10 pages by traffic volume" 图表 |
| **生成结果表** | Search / Traffic / Status / Steps 四列表格，New 徽章 |
| **双栏对比布局** | 左生产流量右测试套件，中间覆盖缺口 |

### Applitools（文案推断）
- Batch 列表 + 状态过滤器；截图对比视图（并排+差异叠加）
- 根因分析视图；批量接受/拒绝相似差异（维护工作流）
- Visual baseline 分组管理

### QA Wolf
- 实时计数器（Tests running / retrying / passed 动画数字）
- 失败视频回放；CI 工作流五步可视化（PR→回归→冒烟→合并→发布）

### Mabl
- 管理层报表仪表盘；测试质量评分；Flakiness 报告（区分真实失败/环境噪音）
- Test Impact Analysis；趋势图追踪套件健康度；失败自动分类

### Testim
- 步骤化测试编辑器；截图对比；错误聚合；团队协作视图

## 二、我们的差距（诚实清单）

| # | 差距 | 竞品做法 | 我们现状 | 严重度 |
|---|---|---|---|---|
| 1 | **无仪表盘首页** | 落地即概览：统计+趋势+活动 | 落地=技能列表，无全局视角 | 致命 |
| 2 | **无数据可视化** | 趋势图/分布图/流量图 | 纯文字+数字 | 致命 |
| 3 | **信息密度低** | 一屏多面板（标签+卡片+图表+列表） | 一屏一个简单表格 | 高 |
| 4 | **无搜索/过滤** | 全局搜索+状态/环境过滤器 | 无 | 高 |
| 5 | **无时间维度** | 时间范围选择器+趋势 | 只有单点状态 | 高 |
| 6 | **无实时感** | 计数器动画/运行中状态 | 全静态 | 中 |
| 7 | **无失败下钻** | 截图对比/视频回放/根因 | 文字归因 | 中 |
| 8 | **视觉简陋** | 渐变/阴影层次/动效/品牌感 | 平面表格风 | 中 |
| 9 | **无环境对比** | PROD vs TEST 并排 | 无 | 低（我们场景不同） |

## 三、UI v2 设计基准（对标后制定）

**信息架构**：登录后落地 `/dashboard`（仪表盘），侧栏 7 项。

**仪表盘四区**（对标 Katalon TrueTest 首屏）：
1. 顶排统计卡（大数字）：技能总数/learned/回放通过率/flaky/报告数
2. 回放趋势图（14 天，SVG 面积图，对标 Mabl 趋势）
3. 四分类分布（最近报告，SVG 环形图）
4. 最近回放活动流（状态点+技能名+耗时+时间，对标 QA Wolf 活动流）

**技能列表**：搜索框+状态/来源过滤器+卡片重设计（置信度进度条）

**报告页**：四分类环形图+分栏强化

**全局**：toast 通知、加载骨架、页面切换过渡

**视觉**：保持零依赖（不引 UI 库），升级令牌体系——更深的阴影层次、
渐变强调色、更大数字排版、卡片 hover 动效。
