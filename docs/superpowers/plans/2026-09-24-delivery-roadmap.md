# SkillLens 交付路线图：从 MVP 到全闭环交付（Phase 2-4，Sprint 7-18）

> 日期：2026-09-24。基于宪法 §0.3 阶段地图倒排，出口标准逐条映射到 Sprint。
> 节奏假设：延续 MVP 的压缩节奏（子代理驱动 SDD），1 Sprint ≈ 0.5-2 个工作日；
> 标注【闸口】的项需用户/团队外部输入，是排期的真实约束。

## 总览

```
Phase 2 真实流量+变更智能（S7-S11）→ 出口：真实流量置信度≥基线80% + 2次真实发版报告被认可
Phase 3 夜间工程（S12-S15）        → 出口：1个真实需求夜间自动开发+测试，晨间评审通过率可接受
Phase 4 全闭环交付（S16-S18）      → 出口：1个付费团队在私有化环境跑完整闭环
```

| 台阶 | Sprint | 形态 | 为什么是这个时机 |
|---|---|---|---|

## Phase 2：真实流量 + 变更智能（S7-S11）

### S7 技术债清障 + 演示基线固化 ✅计划已写
详见 `2026-09-24-sprint7-tech-debt-baseline.md`。产出：complete() 异常落库、孤儿 404、100KB 截断、window_params 对账、**baseline_snapshot（C2 对比锚）**。

### S8 UI Before/After 快照（spec §4.3 层 2(b)）
- 插件侧：锚点动作前 1s + 网络空闲后 2s 的轻量状态快照（表单值/状态标签文本/表格行数），复用回放快照 schema
- server：state_before/state_after 落 semantic_action；层 2 断言升级支持 ui_text 对比
- 回放：执行前后各采一次快照，PASS/FAIL 证据含 UI 前后对比
- 依据：saveFormConfig 100KB reqBody 不含字段默认值（Sprint 3 发现），UI 快照是补盲唯一手段
- 验收：修改字段默认值场景，层 2 断言能 FAIL（现在测不出）；E2E 修复轮预留

### S9 工作台 v0（报告可视化）
- FastAPI 静态托管 + 轻前端（无重框架，Vite+原生或 Vue 单页）；页面：Skills 列表/详情（骨架+变量+断言+证据计数）、Delta 报告四分类视图、回放触发+结果
- 只读+触发两类操作，不做编辑；数据全部来自现有 API
- 验收：不看 DB/curl 能完成一次"看报告→触发回放→看结果"全流程；浏览器实看（宪法工作方式）
- 这是 Phase 2 出口"团队认可"的评审载体

### S10 真实流量切换（C2 生效）【闸口：团队测试常用系统的选定与访问授权】
- 目标系统适配：URL 模板/状态信号/定位策略配置化（兑现 D1"只改配置不改核心"）
- 噪声处理核心：走错/中断/并行任务/废路径过滤（策略：窗口序列频次+骨架支持度）
- 多路径分桶：skill_strategy 表落地 + evidence_edge 基础表（spec §5 定义未实现项）
- 真实流量采集 → 与 S7 baseline 对比置信度
- 验收：真实流量归纳出 ≥1 个 learned Skill，置信度 ≥ 基线 80%，噪声窗口过滤率有数据

### S11 真实发版验收 ×2【闸口：两次真实需求变更 + 团队评审】
- 每次发版：需求→Expected Delta→新版本 Observed→四分类报告→团队评审核签
- 达成 = Phase 2 出口 → 进 Phase 3

## Phase 3：夜间工程（S12-S15）

### S12 Agent 运行时底座
- 引入 LangGraph（宪法 D4：Phase 3 才引入）；夜间调度器（cron 驱动 S10 的回放套件）
- Impact Analysis 基础：版本 diff（UI/API/状态）→ evidence_edge 图遍历 → 受影响 Skill 选择 → 定向回归清单
- 验收：一次 njmind 变更构造，自动选出受影响 Skill 并只回归它们

### S13 Coding Agent 夜间开发【闸口： njmind 开发账号/仓库或 API 的自动化授权】
- 需求 → Living System Model + Expected Delta → 开发计划 → 代码生成（对低代码 njmind：经其配置 API 自动改表单/逻辑）→ 构建
- C1 延伸： destructive 变更默认 shadow（只出计划不执行），确认后才执行
- 验收：1 个表单级需求夜间自动实现，次日人工核对生效

### S14 编排画布 v1（图形化编排主体）
- 节点类型：需求源/Coding/Testing/回归选择/评审输出；连线=数据流；每节点可配置参数与门控
- 后端执行器把画布 DAG 编译成 LangGraph 运行；运行历史与节点产物可视化（截图/断言/报告下钻）
- 验收：在画布拖出"需求→夜间开发→定向回归→晨间报告"并真实跑通一次

### S15 晨间评审 + Skill 演化
- Review 门户雏形：PR 式评审流（变更摘要+证据链+四分类），通过/驳回/打回
- Skill 版本演化管理（spec §4.3 version 字段落地：re-learn 产生新版本，旧版本断言历史保留）
- 验收：一次需求全夜间流水线，晨间评审通过 → Phase 3 出口

## Phase 4：全闭环交付（S16-S18）

### S16 全闭环贯通
- 白天录需求 → 夜间 Coding+Testing → 晨间评审 → 归档学习（模型自我更新）完整转起来
-【闸口：试点团队/客户确定】

### S17 交付加固
- Review 门户完善、安装器/部署向导打磨、备份恢复演练、安全审计（凭据/日志/网络边界复查）、性能（100KB diff/回放并发）
- 镜像瘦身与 ghcr 预拉方案（遗留项收尾）

### S18 试点运行
- 试点团队真实使用 ≥2 周，反馈迭代；出口：1 个付费团队私有化环境跑完整闭环 = 交付

## 排期与闸口依赖（关键路径）

```
S7 → S8 → S9 → [S10 闸口:目标系统授权] → [S11 闸口:两次真实发版]
                                              ↓ Phase 2 出口
     S12 → [S13 闸口:开发自动化授权] → S14 → S15
                                              ↓ Phase 3 出口
     [S16 闸口:试点团队] → S17 → S18 = 交付
```
